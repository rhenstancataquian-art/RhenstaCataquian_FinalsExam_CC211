# Prompt Log — The Dragon's Hoard

This log records the principal development prompts used to plan and generate the project. The result summaries describe the files and behavior included in this delivered version. They are not a claim of exhaustive browser/device testing.

| Technique or Framework | Purpose | Exact Prompt | Result Summary | Evaluation | Improvement |
|---|---|---|---|---|---|
| RCTFC (Role, Context, Task, Format, Constraints) | Define the project scope and technical boundaries | "Act as a senior UI/UX designer and professional frontend web developer. Build The Dragon's Hoard, a responsive fantasy-themed D&D merchandise store using HTML5, CSS3, Vanilla JavaScript, Bootstrap 5, Bootstrap Icons, and LocalStorage. Keep it frontend-only, with no backend, database, or real payment gateway." | Established the visual direction, seven-page scope, frontend-only architecture, and sample-data approach. | Clear scope and constraints help prevent accidental backend or framework dependencies. | Add a prioritized acceptance checklist and test cases before implementation. |
| UI/UX design prompting | Create a consistent fantasy storefront | "Use a dark fantasy palette with #171717, #24201D, #C9A45C, #F2E8D5, #A6A09A, and #8B2929. Use serif headings, readable sans-serif body text, gold actions, clear product cards, responsive spacing, subtle hover states, and accessible focus indicators." | Added a shared CSS design system, responsive navigation, hero area, category cards, product cards, content panels, and footer. | The palette and reusable styles support a consistent theme across pages. | Review contrast and spacing at actual mobile and desktop viewport sizes. |
| Data-driven JavaScript | Render a catalog without a backend | "Create at least 20 sample products across Books, Miniatures, Maps, and Dice. Store product IDs, names, category, price in PHP, rating, stock, image path, description, specifications, and optional tag in a JavaScript array. Render product cards from that data." | Added 20 sample product records in `assets/js/products.js`; shop and featured products are generated from the shared array. | Centralized data avoids duplicating product information across catalog and details views. | Add a product schema check and separate inventory logic if a backend is introduced. |
| Search, filtering, and sorting | Help shoppers discover products | "Implement case-insensitive product search, category filtering, maximum-price filtering, and sorting by featured order, price ascending, price descending, rating, and name. Include a clear-filters action and empty-results state." | Added interactive shop controls and result count in `pages/shop.html`. | Covers the requested basic discovery workflow. | Add pagination and more filter combinations for a larger catalog. |
| LocalStorage state management | Persist cart and wishlist in the browser | "Use LocalStorage to save cart line items as product IDs and quantities, and wishlist entries as product IDs. Recalculate counters and totals whenever data changes. Handle missing or malformed stored JSON safely." | Added shared storage helpers, cart/wishlist counters, cart quantity editing, item removal, and wishlist controls. | State persists across refreshes in the same browser profile. | Add storage versioning and stronger validation for imported or corrupted values. |
| Checkout validation | Simulate a safe frontend order flow | "Build a checkout form for name, email, phone, address, city, postal code, and payment method. Validate required fields and email, show clear feedback, do not request card details, generate a random order number, and store a simulated order locally." | Added native and Bootstrap validation, payment method choices, order summary, LocalStorage order record, and confirmation modal. | Meets the demo checkout requirement without collecting sensitive card data. | Add server-side validation and payment provider integration only in a separately authorized production project. |
| Accessibility and responsive layout | Make the site usable across devices | "Use Bootstrap responsive grids and a collapsible mobile navigation. Add associated form labels, descriptive image alt text, accessible names for icon buttons, live status messages, keyboard focus styles, and readable contrast." | Added responsive Bootstrap layouts, labels, alt text, aria labels/live regions, and visible focus styling. | Accessibility support is included in markup and CSS. | Conduct keyboard-only, screen-reader, and real-device checks before final academic submission. |
| Documentation prompting | Explain setup, scope, and limitations honestly | "Write README.md with project description, student details, users, objectives, features, technologies, local setup steps, AI tool contribution, testing status, limitations, and external credits. Write PROMPT_LOG.md as a Markdown table with technique, purpose, exact prompt, result, evaluation, and improvement." | Added both documentation files with project-specific details and explicit notes about CDN use and unperformed exhaustive testing. | Documents the delivered implementation without claiming unverified test results. | Update the testing section with actual observations after manual testing on the student's devices. |
